# Точки на карте — дизайн

Дата: 2026-09-19

## Задача

Заменить форму добавления места под картой на прямое взаимодействие с картой: клик по карте ставит пин с плюсиком, клик по пину открывает тултип добавления точки. У точки появляется иконка. Список точек слева получает drag-n-drop между днями и внутри дня. На карте появляется поиск мест.

## Что уже есть в коде

- Таблица `places`: `id`, `trip_id`, `city_id NOT NULL`, `visit_date`, `name`, `google_maps_url`, `google_place_id`, `latitude`, `longitude`, `position`, `created_by`. Иконки нет.
- `POST /trips/:tripId/cities/:cityId/places` и `PATCH /trips/:tripId/places/:placeId`. Эндпоинта удаления нет.
- `PATCH` обновляет поля через `coalesce`, поэтому сбросить `visit_date` в `NULL` невозможно.
- `PATCH` разрешён только владельцу поездки или автору точки.
- Сервер валидирует, что `visit_date` лежит внутри `arrival_date..departure_date` города.
- `src/components/GoogleMapPicker.tsx` — карта на экране города: клик по карте отдаёт координаты в форму, точки рисуются `google.maps.Marker` с числовыми подписями.
- `CityPanel` в `src/App.tsx` — слева список дней с точками, справа карта и форма `route-form`.
- Иконки интерфейса — плоские SVG Material Symbols в `public/assets/icons/`, отдаются через `<img>` компонентом `Icon`.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Контекст карты | Экран города, как сейчас. Точка принадлежит городу, дата — внутри дат города |
| Поиск | Places API (New), `AutocompleteSuggestion` + `AutocompleteSessionToken` |
| Клик по существующей точке | Тултип просмотра с отдельной кнопкой редактирования; удаление — внутри режима редактирования |
| Drag-n-drop | Между днями и порядок внутри дня |
| Маркеры | Все точки города видны. Точки активного дня полноцветные, остальные приглушены. Без активного дня — все полноцветные |
| Дата по умолчанию | Активный день, если выбран; иначе «Без даты» |
| Набор иконок | 8 штук |
| Права | Править, перетаскивать и удалять точки может любой участник поездки |
| Технология маркеров | `AdvancedMarkerElement` (маркер — HTML-элемент), Map ID `a906a0e6ca962cd2c1e96f72` |
| Технология DnD | `@dnd-kit/core` + `@dnd-kit/sortable` + `@dnd-kit/utilities` |

## Модель данных

Миграция `apps/api/src/migrations/020_place_icons.sql`:

```sql
ALTER TABLE places ADD COLUMN IF NOT EXISTS icon text NOT NULL DEFAULT 'default';
```

Допустимые значения проверяются на сервере по белому списку из восьми ключей. Неизвестный ключ → `400`. Существующие точки получают `default`.

## Сервер

`apps/api/src/server.ts`:

1. `POST /trips/:tripId/cities/:cityId/places` принимает необязательный `icon`, по умолчанию `default`.
2. `PATCH /trips/:tripId/places/:placeId` принимает `icon`.
3. `PATCH` учится ставить `visit_date = NULL`. «Поле не прислали» и «прислали `null`» различаются через наличие ключа в теле запроса, а не через `coalesce`. Если дата присылается непустой, сохраняется проверка попадания в даты города.
4. Из `PATCH` убирается ограничение «только владелец или автор» — править может любой участник поездки. Проверка `requireTripRole` остаётся.
5. Новый `DELETE /trips/:tripId/places/:placeId` — доступен любому участнику поездки, возвращает `204`.
6. Новый `PATCH /trips/:tripId/places/:placeId/move` с телом `{ visitDate: string | null, position: number }`, где `position` — индекс в целевом дне, считая с нуля. В одной транзакции: удалить точку из порядка исходного дня и перенумеровать оставшиеся, вставить в целевой день на указанную позицию и перенумеровать. Возвращает `{ places: ApiPlace[] }` — все точки города после перестановки. Целевая дата валидируется по датам города.
7. Экспорт `.travelspace` включает `icon`, импорт его читает. У старых файлов без поля берётся `default`.

Публичная выдача поездки уже отдаёт все поля `places`, поэтому `icon` попадёт туда без изменений.

## Клиент

### `src/api.ts`

- `ApiPlace` получает `icon: PlaceIconKey`.
- `createPlace` и `updatePlace` принимают `icon`.
- `updatePlace` умеет присылать `visitDate: null`.
- Добавляются `deletePlace(tripId, placeId)` и `movePlace(tripId, placeId, { visitDate, position })`.

### `src/placeIcons.ts`

Каталог из восьми записей `{ key, label, file }`, тип `PlaceIconKey`, функция сопоставления типа места Google с ключом иконки (`restaurant` → `food`, `cafe` → `cafe`, `lodging`/`hotel` → `hotel`, `store`/`shopping_mall` → `shopping`, `park` → `nature`, `train_station`/`subway_station`/`airport`/`bus_station` → `transport`, `tourist_attraction`/`museum` → `sightseeing`, остальное → `default`).

### `src/components/PlacesMap.tsx`

Заменяет `GoogleMapPicker.tsx`, который удаляется.

- Загрузка Maps JS с `libraries=places,marker` и `mapId` из `VITE_GOOGLE_MAPS_MAP_ID`.
- Маркеры точек — `AdvancedMarkerElement`, содержимое — `div.place-marker` с `<img>` глифа. Приглушение неактивных дней — CSS-класс с пониженной непрозрачностью.
- Клик по пустому месту карты ставит черновой пин `add-pin.svg`. Повторный клик по карте переставляет его. `Esc` убирает черновой пин и закрывает тултип.
- Клик по черновому пину открывает тултип добавления. Клик по маркеру существующей точки открывает тултип просмотра.
- Тултип рендерится React-порталом в кастомный `google.maps.OverlayView`, привязанный к координате, поэтому следует за картой при панорамировании и зуме. Штатный `InfoWindow` не используется: его собственное оформление не сводится к стеклянному тёмному стилю проекта.
- Для точек без координат сохраняется существующий фоллбэк через `Geocoder` с кэшем и колбэком `onResolvePlace`.
- Если ключ не задан, компонент по-прежнему отдаёт iframe-заглушку без интерактива.

### `src/components/PlacePopup.tsx`

Один компонент, три состояния.

- **Просмотр**: глиф, название, дата или «Без даты», ссылка «Открыть в Google Maps», кнопка перехода в редактирование.
- **Добавление**: поле названия (обязательное), выбор одной из восьми иконок, селект даты со значениями «Без даты» и днями города, кнопки «Сохранить» и «Отмена».
- **Редактирование**: то же, что добавление, плюс удаление точки.

Сохранение с пустым названием заблокировано.

### `src/components/MapSearch.tsx`

Поле поиска поверх карты. `AutocompleteSuggestion.fetchAutocompleteSuggestions()` с `AutocompleteSessionToken`, ввод дебаунсится, запрос смещается к текущей области карты через `locationBias`. Токен сеанса пересоздаётся после каждого выбранного результата.

Выбор подсказки: карта центрируется на месте, ставится черновой пин, сразу открывается тултип добавления с подставленным названием и иконкой, угаданной по типам места. Название и иконку можно поменять до сохранения.

### `src/components/PlaceDayList.tsx`

Список дней слева, вынесенный из `CityPanel`.

- Состояние активного дня: клик по заголовку выделяет день, повторный клик снимает выделение.
- `DndContext` поверх списка. Каждый день, включая «Без даты», — дроп-зона, принимающая дроп даже будучи пустой. Каждая точка — сортируемый элемент.
- Сенсор с порогом активации 5px, чтобы обычный клик по точке продолжал открывать её на карте.
- Перенос в другой день меняет дату, перетаскивание внутри дня меняет позицию. И то и другое уходит одним запросом `movePlace`.
- Обновление оптимистичное: состояние меняется сразу, при ошибке сервера — откат и перезагрузка поездки, как уже сделано с документами в `CityPanel`.

### `src/App.tsx`

- `Place` получает поле `icon`.
- `CityPanel` теряет форму `route-form` и связанные состояния `place`, `placeUrl`, `placeCoordinates`, `selectedDate`, а также обработчик `addPlace`. Карта и список уезжают в свои модули, компонент заметно сокращается.
- Появляется состояние активного дня, прокидываемое в список и в карту.
- `initialDate`, приходящий по ссылке «Добавьте места для посещения» с дневной карточки календаря, теперь делает соответствующий день активным вместо предвыбора даты в удалённой форме.
- Новые обработчики `onDeletePlace` и `onMovePlace` по образцу существующих `onAddPlace` и `onUpdatePlace`.
- Создание точки прибытия из формы транспорта (`saveTransport`) проставляет `icon: 'transport'`.

### Режим только для чтения

В публичном просмотре поездки работают карта, маркеры и тултип просмотра. Черновой пин, поиск, редактирование, удаление и drag-n-drop отключены. Признак берётся из уже существующего `readOnly` у `Dashboard`.

### Стили

`src/styles.css`: стили маркера и его приглушённого состояния, тултипа, поля поиска с выпадающим списком, состояний перетаскивания и дроп-зоны в списке. Правила `.route-form` удаляются.

Отдельных макетов пока нет — оформление собирается на существующих токенах дизайн-системы и заменяется, когда макеты появятся.

## Зависимости и конфигурация

- Добавляются `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`.
- `.env` и `.env.example`: `VITE_GOOGLE_MAPS_MAP_ID`, значение `a906a0e6ca962cd2c1e96f72`.
- `VITE_GOOGLE_MAPS_API_KEY` и `VITE_GOOGLE_MAPS_MAP_ID` заданы в локальном `.env`, который не хранится в Git. В `.env.example` обе переменные остаются пустыми шаблонами с комментариями.
- Map ID и переменная пробрасываются в `Dockerfile` и `compose.yaml` рядом с существующим ключом.
- В Google Cloud включены Maps JavaScript API и Places API (New); проверено запросом автодополнения. На обоих стоит поставить ограничение квоты, чтобы не выйти за бесплатный лимит.
- Ключ ограничен по HTTP-referer. В белом списке есть `http://localhost:4173` — порт дев-сервера из `package.json`. При смене порта Vite или добавлении нового домена referer нужно добавить в ограничения ключа, иначе поиск молча начнёт отвечать `API_KEY_HTTP_REFERRER_BLOCKED`.

## Границы задачи

Не делается: построение маршрута по точкам и его открытие в Google Maps, точки вне города, перенос точек между городами, офлайн-режим карты, загрузка фотографий к точке.

## Проверка

- `pnpm typecheck`, `pnpm build`, `pnpm build:api`.
- Миграция применяется на чистой базе и на базе с существующими точками.
- Ручной сценарий в браузере после появления ключа: добавление точки кликом, добавление через поиск, просмотр, редактирование, удаление, перенос между днями, сортировка внутри дня, перенос в «Без даты» и обратно, публичный просмотр без прав на правку, экспорт и импорт поездки с иконками.
