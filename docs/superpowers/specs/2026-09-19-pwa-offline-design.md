# PWA и оффлайн-режим — дизайн

Дата: 2026-09-19

## Задача

Сделать приложение устанавливаемым PWA и научить его работать без сети. Открытая поездка вместе со всеми своими ресурсами — фоном, картинками городов, аватарами участников, документами и билетами — должна быть доступна оффлайн. То, что не нужно прямо сейчас, докачивается в фоне. Service worker живёт под префиксом `/travel/`.

Рядом с названием поездки появляется кольцо прогресса, пока кэш не полон, и оффлайн-иконка, когда сети нет.

## Что уже есть в коде

- SPA публикуется под `BASE_PATH` (по умолчанию `/travel`). Префикс читают и `vite.config.ts`, и `apps/api/src/config.ts` — источник правды один.
- Fastify отдаёт собранный SPA через `@fastify/static` с `prefix: ${basePath}/` и `wildcard: false`, а неизвестные пути под префиксом заворачивает в `index.html` (`apps/api/src/server.ts:75-88`, `:855-861`). Клиентские маршруты `/travel/join/<token>` и `/travel/view/<token>` существуют только в браузере.
- Весь обмен с API идёт через `fetch` с заголовком `Authorization: Bearer` (`src/api.ts:130-153`). Картинки и документы не подставляются в `src` напрямую: они скачиваются как blob и превращаются в object URL. Значит service worker перехватывает вообще все ресурсы поездки, включая приватные.
- Поездка приходит одним запросом `GET /travel/api/trips/:id` со всеми городами, местами, задачами, документами и участниками (`ApiTripDetails`). Этого одного ответа достаточно, чтобы построить полный список ресурсов поездки.
- Все файлы поездки — строки таблицы `documents`, различаются полем `category`: `trip-background`, `city-image`, `train-in:*`, `train-out:*` и прочие. Скачиваются по `/api/documents/:id/download`, в публичном режиме — по `/api/public-trips/:token/documents/:id`.
- Аватар участника — `/api/trips/:tripId/members/:memberId/avatar`, свой — `/api/me/avatar`.
- Сквозной проп `readOnly` уже протянут через весь дашборд: он выключает правки в публичном режиме просмотра по view-ссылке.
- Карта — Google Maps JS API, грузится с их CDN (`src/components/PlacesMap.tsx:23-36`). Ошибка загрузки сейчас глушится `.catch(() => undefined)`, и оффлайн на месте карты остаётся пустой прямоугольник.
- `public/assets/autumn-garden.jpg` весит 5.4 МБ — это фон поездки по умолчанию. Остальная статика — мелкие PNG-заглушки и SVG-глифы.
- Тесты — vitest, окружение `node`, только чистые функции (`src/placeIcons.test.ts`, `apps/api/src/places.test.ts`).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Правки оффлайн | Только чтение. Очереди изменений и синхронизации нет |
| Объём кэша | Открытая поездка целиком + список поездок и их фоны |
| Сборка SW | `vite-plugin-pwa` в режиме `injectManifest`: precache от workbox, вся остальная логика своя |
| Индикатор | Кольцо прогресса по числу файлов; нет сети — вместо кольца оффлайн-иконка |
| Блокировка правок оффлайн | Переиспользовать существующий `readOnly`, а не заводить новый флаг |
| Точки оффлайн | Попап точки работает без карты, ссылка ведёт в локальное приложение карт |
| Обновление версии | Новый SW ждёт и берёт управление при следующем холодном старте, без авто-перезагрузки |

## Кэши и стратегии

Пять независимых кэшей. Имена версионированные; на `activate` удаляется всё, что начинается с `travel-` и не входит в текущий набор.

| Кэш | Что попадает | Стратегия | Обоснование |
|---|---|---|---|
| precache workbox | `index.html`, JS, CSS, SVG, `manifest.webmanifest` | precache при install | оболочка приложения, ревизии берутся из хэшей Vite |
| `travel-assets-v1` | `/travel/assets/**` — JPG и PNG | CacheFirst | `autumn-garden.jpg` на 5.4 МБ в precache утяжелил бы установку; докачивается фоновым префетчем |
| `travel-data-v1` | GET `/travel/api/trips`, `/trips/:id`, `/me`, `/public-trips/:token` | NetworkFirst, `networkTimeoutSeconds: 4` | свежесть важнее кэша, но на плохой сети поездка всё равно открывается |
| `travel-media-v1` | `/api/documents/:id/download`, `/api/public-trips/:token/documents/:id` | CacheFirst | документ по id неизменяем: правка создаёт новую строку с новым id |
| `travel-avatars-v1` | любой GET, заканчивающийся на `/avatar` | StaleWhileRevalidate | аватар меняется по тому же URL |

Всё остальное маршрутов не имеет и уходит в сеть напрямую: Google Maps, тайлы, любые мутации. Чужие тайлы кэшировать и нельзя по правилам Google, и бесполезно.

Навигационные запросы обслуживает `NavigationRoute` с `createHandlerBoundToURL(<base>index.html)` и denylist на `<base>api/` — иначе прямой заход на `/travel/view/<token>` оффлайн не откроется.

### Разбор запроса

Чистая функция в отдельном модуле, чтобы её можно было протестировать вне SW:

```ts
classifyRequest(method: string, url: URL, base: string):
  'asset' | 'data' | 'media' | 'avatar' | null
```

Возвращает `null` для всего, что не `GET`, для другого origin и для путей вне `base`. `base` берётся из `new URL(self.registration.scope).pathname`, а не из отдельной константы: иначе префикс пришлось бы задавать в третьем месте.

## Префетч и прогресс

Список ресурсов строит приложение, а не service worker. Приложение и так разбирает `ApiTripDetails` и владеет константами путей к статике, поэтому знание о форме API остаётся в одном месте, а SW остаётся тупым загрузчиком.

### Что входит в список

`tripResourceUrls({ trip, hasOwnAvatar, publicToken? }): string[]` — чистая функция. Порядок важен: сначала то, что видно на экране сразу, потом тяжёлые PDF.

1. Статические картинки: `autumn-garden.jpg`, `city-placeholder.png`, `hotel-placeholder.png`, `ticket-placeholder.png`, `person-default.png`, `person-member.png`, `person-owner.png` — все с префиксом `import.meta.env.BASE_URL`.
2. Документы категорий `trip-background` и `city-image`.
3. Аватары участников с `has_avatar`, затем свой аватар, если он есть.
4. Все остальные документы поездки — билеты, брони, прочие файлы.

Список дедуплицируется с сохранением порядка. При `publicToken` документы строятся как `/api/public-trips/<token>/documents/<id>`, иначе как `/api/documents/<id>/download`.

Отдельная функция `tripsListResourceUrls(trips): string[]` даёт фоны из `background_document_id` для экрана списка поездок.

Задача префетча в SW всегда одна. Когда поездка открыта, приложение отправляет один список: фоны списка поездок плюс ресурсы открытой поездки. Когда открыт только список, отправляется список с `tripId: null`. Кольцо живёт лишь на экране поездки и реагирует только на сообщения со своим `tripId`.

### Протокол сообщений

Страница → SW:

- `{ type: 'prefetch', tripId: string | null, token, urls }` — начать или продолжить докачку. Новое сообщение с другим `tripId` отменяет предыдущую задачу.
- `{ type: 'clear-private' }` — удалить `travel-data-v1`, `travel-media-v1`, `travel-avatars-v1`.

SW → страница:

- `{ type: 'prefetch-progress', tripId, done, total }`
- `{ type: 'prefetch-done', tripId }`
- `{ type: 'prefetch-blocked', tripId, reason: 'quota' | 'network' }`
- `{ type: 'network', online }`

### Как работает загрузка

SW сначала отсеивает URL, уже лежащие в нужном кэше, и берёт `total` из полного списка, а `done` — из числа уже закэшированных. Поэтому после перезагрузки при полном кэше прогресс сразу равен `total`, и кольцо не мигает впустую.

Качает по два файла параллельно. Для URL под `<base>api/` подставляет `Authorization: Bearer <token>`, для статики — нет. Токен живёт только в памяти SW и никогда не попадает ни в кэш, ни в IndexedDB. После перезапуска SW префетч не возобновляется сам — его заново инициирует страница при следующей загрузке.

`QuotaExceededError` останавливает задачу и отправляет `prefetch-blocked` с `reason: 'quota'`. Сетевая ошибка — то же самое с `reason: 'network'`; докачка возобновится при следующем открытии поездки.

Один раз после входа приложение зовёт `navigator.storage.persist()`. Для установленной PWA Chrome выдаёт разрешение молча, и кэш перестаёт быть кандидатом на вытеснение.

## Индикатор у названия поездки

Новый компонент `CacheIndicator` встаёт перед названием внутри `TypographyGroup title={...}` в `TripSidebar` — `title` принимает `ReactNode`, менять компонент типографики не нужно.

Состояние живёт в хуке `useOfflineCache`, который владеет всей перепиской с SW:

```ts
type CacheState =
  | { kind: 'idle' }
  | { kind: 'prefetching'; tripId: string; done: number; total: number }
  | { kind: 'ready' }
  | { kind: 'blocked'; reason: 'quota' | 'network' }
```

Флаг `online` хранится отдельно. Что рисуется:

| Условие | Вид |
|---|---|
| `!online` | оффлайн-иконка `cloud-off.svg` |
| `online` и `kind === 'prefetching'` | кольцо, заполненное на `done / total` |
| `online` и `kind === 'blocked'` | замершее кольцо, причина в `title` |
| иначе | ничего |

Кольцо — SVG 20 px, окружность со `stroke-dasharray` по проценту. Прогресс считается по числу файлов, не по байтам.

Оффлайн определяется двумя источниками сразу: события `online`/`offline` на `window` реагируют мгновенно, а сообщения `network` от SW ловят реальный случай — Wi-Fi есть, интернета нет, и `navigator.onLine` при этом врёт.

Новый глиф `public/assets/icons/cloud-off.svg` берётся из Material Symbols Outlined и приводится к формату существующих: `height="24px"`, `width="24px"`, `viewBox="0 -960 960 960"`, `fill="#FFFFFF"`. Ключ `cloud-off` добавляется в union `IconName`.

## Оффлайн — только чтение

Оффлайн переиспользует существующий `readOnly`: `readOnly={readOnly || offline}`. Новой логики блокировок не появляется, а вся уже написанная — отключённые строки городов, скрытые действия, `readOnly` на текстовых полях — начинает работать оффлайн бесплатно.

Побочный эффект: оффлайн ссылка «участники» становится текстом вместо кнопки приглашения. Это правильно — создание приглашения требует сети в любом случае.

Осознанный компромисс: `readOnly` сейчас означает «публичный просмотр по ссылке». Оффлайн — второй смысл того же флага. Пока правила совпадают полностью, разделять рано; если разойдутся, флаг придётся расщепить.

## Точки и карта оффлайн

Сейчас клик по точке в списке оффлайн не делает ничего: эффект фокуса в `PlacesMap` начинается с `if (!map || !focusRequest) return`, выходит досрочно и не зовёт даже `onFocusHandled`, из-за чего `focusRequest` залипает.

Что меняется:

- Область карты оффлайн показывает явное «Карта недоступна без интернета» вместо пустого прямоугольника.
- Эффект фокуса перестаёт требовать `mapRef.current`: он всегда выставляет `selectedId`, панорамирует только при наличии карты и всегда зовёт `onFocusHandled`.
- `PlacePopup` в режиме `view` рендерится статичной карточкой в области карты, когда `MapOverlay` невозможен. Сам компонент не меняется — он и так не зависит ни от карты, ни от Google Maps API. Редактирование оффлайн закрыто через `readOnly`, поэтому нужен ровно режим `view`.

Ссылка в попапе строится новой чистой функцией `placeMapsHref(place)`:

- есть координаты → `https://www.google.com/maps/search/?api=1&query=<lat>,<lng>`;
- нет координат → сохранённый `google_maps_url`, как сейчас.

Причина: сохранённая ссылка часто короткая, вида `maps.app.goo.gl/...`, а короткую ссылку без сети не развернуть — приложение карт откроется и упрётся в редирект. Координатная форма — документированный Maps URLs API; её домен матчится app-link-ами Google Maps и на Android, и на iOS, поэтому установленное приложение открывается локально и ставит пин из офлайновых карт. Правило применяется всегда, не только оффлайн: онлайн оно тоже точнее.

## Манифест, иконки, установка

- `vite-plugin-pwa` в режиме `strategies: 'injectManifest'`, `srcDir: 'src'`, `filename: 'sw.ts'`. `scope` и `start_url` выводятся из `base` конфига Vite, отдельной константы префикса не появляется.
- `injectManifest.globPatterns`: `['**/*.{js,css,html,svg,webmanifest}']`. Крупные растровые картинки в precache не идут — их забирает `travel-assets-v1` и фоновый префетч.
- Манифест: `name` и `short_name` — `Travel Space`, `display: 'standalone'`, `background_color` и `theme_color` — `#080808`, `lang: 'ru'`.
- Иконки `public/assets/app-icon-192.png`, `app-icon-512.png`, `app-icon-512-maskable.png` — белый глиф `planet.svg` на фоне `#080808`, тот же логотип, что на экранах авторизации. Растрируются через canvas в браузере один раз и коммитятся. Никакого нового тулинга в сборке. Файлы лежат в `public/assets/`, а не в `public/assets/icons/`, чтобы не смешиваться с глифами интерфейса, по именам которых резолвится компонент `Icon`.
- В `index.html` добавляется `apple-touch-icon` относительным путём — абсолютный не переписался бы под `base`.
- Регистрация — `virtual:pwa-register` в `src/main.tsx`; в `src/vite-env.d.ts` добавляется ссылка на типы `vite-plugin-pwa/client`.
- `devOptions.enabled: false` — в dev service worker не регистрируется. Проверка оффлайна идёт только на собранном приложении.
- В `vite.config.ts` в секцию `preview` добавляется тот же proxy, что уже есть в `server`: без него собранную PWA негде проверить с живым API.

## Обновление версии и приватность

Новый service worker после установки ждёт и берёт управление при следующем холодном старте. `skipWaiting` и авто-перезагрузка не используются: перезагрузка посреди незакрытой формы города потеряла бы введённые данные.

При выходе из аккаунта приложение отправляет SW `clear-private`, тот удаляет `travel-data-v1`, `travel-media-v1` и `travel-avatars-v1`. Без этого следующий пользователь того же браузера увидел бы чужую поездку из кэша: ключ Cache API — это URL, а не токен.

Кэш оболочки и статики при выходе сохраняется — в нём нет ничего приватного.

## Тесты

Всё тестируемое вынесено в чистые функции, окружение vitest остаётся `node`.

- `classifyRequest` — раскладка по пяти кэшам: документ, публичный документ, аватар, JSON поездки, статика; `null` для POST, для Google Maps, для чужого origin и для путей вне базы.
- `tripResourceUrls` — правильный набор URL из фикстуры `ApiTripDetails`; порядок «картинки раньше PDF»; пропуск участников без `has_avatar`; дедупликация; ветка `publicToken`.
- Редьюсер `cacheState` — переходы `idle → prefetching → ready`, `blocked` при квоте, игнорирование сообщений с чужим `tripId`, корректный процент.
- `placeMapsHref` — координаты дают форму `?api=1&query=lat,lng`, их отсутствие возвращает сохранённую ссылку.

## Проверка вручную

1. `pnpm typecheck`, `pnpm test`, `pnpm build`.
2. `pnpm preview` с запущенным API: приложение устанавливается, в DevTools → Application виден зарегистрированный SW со scope `/travel/`.
3. Открыть поездку, дождаться исчезновения кольца, в Network включить Offline и перезагрузить: поездка открывается, фон и картинки городов на месте, аватары видны, билет и бронь скачиваются.
4. Оффлайн: правки недоступны, у названия поездки оффлайн-иконка, клик по точке в списке открывает попап, ссылка ведёт в приложение карт.
5. Выйти из аккаунта и убедиться, что приватные кэши исчезли.

## Что не входит

- Очередь оффлайн-правок и синхронизация при возврате сети.
- Кэш карт и тайлов Google.
- Фоновая докачка чужих поездок из списка: кэшируется только открытая, плюс фоны для экрана списка.
- Push-уведомления и Background Sync.
