# Наполнение компонентов Travel Space

Этот документ фиксирует итоговые решения по странице проверки продуктового контента. Живая страница доступна по маршруту `/travel/components?view=content`.

## Назначение и источник истины

Страница собирает на одном экране реальные варианты `Input`, `Select` и `InfoRow`, которые используются в приложении. Она нужна для поиска расхождений в текстах, иконках, состояниях и метаданных без обхода отдельных продуктовых экранов.

Каталог не является параллельным макетом. В нём используются общие компоненты приложения. Если при ревью меняются текст, иконка, состояние или поведение, изменение должно попадать и в реальный продуктовый сценарий. Нельзя исправлять только демонстрационный пример.

Каждый пример сопровождается подписью с местом применения. Внутри всех групп расстояние между соседними примерами равно 24px.

## Вход и навигация

- Кнопка `Контент` находится третьей secondary-кнопкой в карточке профиля администратора на главной странице.
- На странице компонентов отдельной кнопки `Контент` нет.
- Страница использует общий каркас библиотеки компонентов: слева меню, справа содержимое.
- Ширина левой панели — 360px, промежуток до правой области — 32px.
- В левой панели заголовок `Travel Space`, под ним подпись `Наполнение компонентов`.
- Навигация содержит якоря `Input`, `Select`, `Info Row`, `Изображения`.
- Нижняя кнопка `В приложение` возвращает в приложение.
- Текстовые пункты, разделитель и нижняя кнопка имеют одинаковые левую и правую границы.
- Отдельной верхней плашки `Контент компонентов` в правой области нет.

## Input

### Ссылки

| Место применения | Текст | Иконки и состояние |
| --- | --- | --- |
| Создание и редактирование города | `Ссылка Google Maps` | `link` |
| Транспорт: места отправления и прибытия | `Ссылка Google Maps` | `pin-transport`, справа `content-copy` |
| Отель: адрес в Google Maps | `Ссылка Google Maps` | `pin-home`, справа `content-copy` |
| Приглашение участника | заполненная ссылка без подписи `Активная ссылка` | `link`, справа `content-copy`, read-only |
| Публичная ссылка просмотра | заполненная ссылка | `link`, справа `content-copy`, read-only |

Если плавающая подпись и плейсхолдер совпадают, второй текст не выводится. В частности, у ссылки Google Maps не должно быть двух одинаковых строк.

### Названия мест, города и поездки

| Место применения | Текст | Иконка |
| --- | --- | --- |
| Создание и редактирование поездки | `Название поездки` | `book`, та же иконка, что у названия транспорта |
| Добавление и редактирование города | `Название города` | `planet` |
| Транспорт: точка отправления | `Место отъезда` | `public` |
| Транспорт: точка прибытия | `Место приезда` | `public` |
| Отель | `Название места` | `hotel` |

Точки отправления и прибытия используют ассет `public.svg`; подписи и иконки должны совпадать в каталоге и продуктовой форме.

### Название транспорта

Поле зависит от выбранного типа транспорта:

| Состояние | Текст поля |
| --- | --- |
| Тип не выбран | `Название транспорта`, поле disabled |
| Поезд | `Название и номер поезда` |
| Самолёт | `Номер рейса` |
| Автобус | `Название и номер автобуса` |
| Корабль | `Название и номер корабля` |

Поле нельзя заполнять до выбора типа транспорта. У самолёта слово «название» не используется.

### Время и оплата

- Отель: `Заселение с` и `Выселение до`, иконка `time`.
- Блок оплаты транспорта и отеля использует общий денежный `Input`.
- Время заселения, время выселения и общая сумма образуют отдельную четвёртую смысловую группу Input.

## Select

### Даты

- Диапазон поездки в пустом состоянии: `Дата начала – Дата окончания`.
- Заполненный диапазон: `4 октября – 15 октября · 12 дней`.
- Пустая дата прибытия в город: `Приедем`.
- Пустая дата отъезда из города: `Уедем`.
- Заполненные даты всегда содержат день недели через интерпункт: `4 октября · Вс`, `7 октября · Ср`.
- Дата места на карте не имеет плавающей подписи `Дата посещения`: показывается только дата с днём недели либо `Без даты`.
- В транспорте подписи дат: `Уедем` для отправления и `Приедем` для прибытия.

### Время и тип транспорта

- Селект времени города показывает период дня, например `Утро`.
- Если тип транспорта не выбран, селект содержит единственный основной текст `Транспорт` без плавающей подписи `Тип транспорта`.
- Если тип выбран, плавающая подпись — `Тип транспорта`, значение — конкретный тип (`Самолёт`, `Поезд`, `Автобус`, `Корабль`) и его собственная иконка.
- Состояния, в котором подпись `Тип транспорта` сочетается со значением `Транспорт`, быть не должно.

### Ответственные

Используются четыре формулировки:

- `Кто покупает билет`;
- `Кто бронит отель`;
- `Кто составляет план города`;
- `Кто платил`.

Для каждого селекта каталог показывает оба состояния: пользователь не выбран и пользователь выбран. В пустом состоянии формулировка является плейсхолдером. После выбора она поднимается и становится подписью, а ниже появляется имя выбранного человека.

Иконки: билет — `ticket`, отель — `hotel`, план города — `barefoot`, оплата — `face`.

## InfoRow

Каждый пример подписан реальным местом применения. Между соседними строками в каталоге — 24px.

### Города и профиль

- Город в редакторе маршрута интерактивен и имеет hover-эффект.
- Город на дашборде может использовать прозрачную тему и действия отеля/билета.
- Профиль пользователя в каталоге и в боковой панели поездки использует один `InfoRow` с `theme="transparent"`, круглым аватаром, именем и email. Локальная фоновая подложка для примера не добавляется.

### Изображения

- Загруженное фото города: `Фото города`, имя файла, действия редактирования и удаления.
- Пустое фото города: `Прикрепить фото города`, подпись `Лучше в вертикальном формате`.
- Загруженный фон поездки: `Фоновое фото`, имя файла, действия редактирования и удаления.
- Пустой фон поездки: `Прикрепить фоновое фото`, подпись `В хорошем качестве`.

### Документы

- Для транспорта показываются загруженный билет и состояние `Прикрепить билет`.
- Для отеля показываются загруженная бронь и состояние `Прикрепить бронь`.
- Пустые состояния используют подпись `Лучше в PDF формате`.
- У загруженного документа вторичная строка содержит автора загрузки и дату/время, например `Torch · 27 сентября, 14:30`. Тип файла и размер (`PDF · 1,2 МБ`) в этой строке не показываются.
- Загруженный документ имеет действия скачивания и удаления.

### Расходы

Каталог показывает:

- расход отеля с одним плательщиком;
- расход транспорта с несколькими плательщиками;
- итог по участнику с круглым аватаром, количеством платежей и суммой справа.

## Дефолтные изображения

Раздел `Изображения` показывает только системные изображения, которые приложение автоматически подставляет само. Пользовательские и администраторские загрузки в этот раздел не входят.

| Файл | Автоматическое применение |
| --- | --- |
| `autumn-garden.jpg` | фон приложения и поездки по умолчанию |
| `city-placeholder.png` | город без загруженного фото |
| `ticket-placeholder.png` | системное изображение документа билета |
| `hotel-placeholder.png` | системное изображение документа брони отеля |
| `person-owner.png` | аватар владельца без загруженного аватара |
| `person-member.png` | аватар участника без загруженного аватара |

`person-default.png` не включается: интерфейс его автоматически не назначает, даже если файл присутствует среди кэшируемых ресурсов.

## Цветовые токены disabled и иконок

Иконки используют отдельные семантические токены:

| Токен | Значение |
| --- | --- |
| `--color-icon-primary` | белый, 100% |
| `--color-icon-secondary` | белый с той же прозрачностью, что `--color-text-secondary` |
| `--color-icon-disabled` | белый, 30% |

Disabled-текст использует `--color-text-disabled`, также белый с прозрачностью 30%. Эти цвета задаются токенами и общими состояниями компонентов; локально проставлять opacity для каждого поля или каждой иконки нельзя.

## Правило развития каталога

При появлении нового контентного варианта действуют четыре шага:

1. Добавить или обновить вариант в общем компоненте и продуктовом экране.
2. Добавить тот же реальный компонент на страницу наполнения.
3. Подписать место применения и показать существенные состояния: пустое, заполненное, disabled или зависимое.
4. Проверить тексты, иконки, метаданные, hover и расстояние 24px между примерами.
