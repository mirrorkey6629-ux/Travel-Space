# Ошибки, уведомления и подтверждение действий

Статус: **актуальная спецификация**. Документ фиксирует итоговые решения рабочей
сессии по ошибкам, системной обратной связи, удалению и сохранению данных. Реальные
демонстрационные состояния обязаны одновременно присутствовать на странице
`/travel/components?view=content`.

## 1. Как выбирается место для сообщения

Сообщение показывается максимально близко к действию, которое пользователь может
исправить:

1. Ошибка конкретного значения — под соответствующим `Input` или `Select`.
2. Ошибка конкретной строки, файла или сущности — под соответствующим `InfoRow`.
3. Ошибка операции, фонового запроса или всего экрана — уведомлением.
4. Невозможность открыть целый раздел — системным состоянием внутри экрана.

Нельзя дублировать одну ошибку одновременно у элемента и в уведомлении. Серверное
сообщение переводится в один из пользовательских шаблонов ниже; технический текст
сервера напрямую не показывается.

## 2. Ошибка у поля

- Текст: 13px, цвет `--color-text-secondary`.
- Отступ от нижней границы контрола: 8px.
- Перед текстом используется системная иконка предупреждения.
- Если контрол находится в списке, после ошибки до следующего элемента добавляется
  ещё 4px.
- Кнопку сохранения можно нажать, чтобы запустить валидацию и увидеть ошибки. Запрос
  при невалидных данных не отправляется.

### Аккаунт

| Условие | Текст |
| --- | --- |
| В ссылке нет токена приглашения | `Неправильная ссылка` |
| Почта не относится к аккаунту | `Такая почта не зарегистрирована` |
| Не заполнено имя | `Нужно ввести имя` |
| Новый пароль короче 8 символов | `В пароле должно быть не меньше 8 символов` |
| Пароль не совпал при входе | `Неправильный пароль` |
| Новый пароль длиннее 256 символов | `В пароле должно быть меньше 256 символов` |
| Почта уже занята | `Аккаунт с такой почтой уже есть` |

Ограничения длины относятся к созданию и изменению пароля. При входе неверное
значение любой длины сводится к сообщению `Неправильный пароль`.

### Поездка и город

| Условие | Текст |
| --- | --- |
| Нет названия поездки | `Нужно ввести название поезки` |

| Окончание раньше начала | `Дата окончания не может быть раньше даты начала` |
| Нет названия города | `Нужно ввести название города` |
| Не выбрана дата прибытия | `Нужно выбрать дату прибытия` |
| Не выбрана дата отъезда | `Нужно выбрать дату отъезда` |

## 3. Ошибка у `InfoRow`

`InfoRow` использует тот же визуальный примитив ошибки, что поля. В списке после
ошибки также добавляется 4px до следующей строки.

| Контекст | Текст ошибки |
| --- | --- |
| Город не помещается в новые даты поездки | `Даты города находятся вне дат поездки` |
| Неподходящий формат фото | `Проверьте формат файла` |
| Фото превышает лимит | `Слишком тяжёлый файл` |
| Не загрузился билет или бронь | `Попробуйте загрузить ещё раз` |
| Документ не открылся или не скачался | `Попробуйте скачать ещё раз` |
| Участник удаляет чужой файл | `Удалить файл может его автор или владелец поездки` |

У строк выбора фото города и фона подзаголовок заранее сообщает ограничение:
`В формате JPG, PNG, WEBP до 15 МБ`.

## 4. Уведомления

### Устройство компонента

Уведомление содержит заголовок, подзаголовок и контекстные действия:

- одиночная круговая стрелка — повторить тот же запрос;
- две стрелки — получить свежую версию данных;
- крестик — закрыть сообщение без повторения;
- все иконки белые, кнопки имеют secondary-оформление;
- бессмысленное действие не показывается: ошибки выбранного файла имеют только
  крестик, устаревшие данные — только обновление.

### Данные и действия

| Сценарий | Заголовок | Подзаголовок | Действия |
| --- | --- | --- | --- |
| Обычная ошибка сохранения | `Эх, не сохраняется` | `Попробуйте ещё раз` | повторить, закрыть |
| Новые даты поездки исключают города | `Эх, не сохраняется` | `Проверьте даты городов` | закрыть |
| Место второй раз добавляется в тот же день | `Дважды никак в один день` | `Выберите другую дату для точки` | закрыть |
| Не загрузились данные | `Эх, не загружается` | `Попробуйте ещё раз` | повторить, закрыть |
| Не выполнилось удаление | `Эх, не удаляется` | `Попробуйте ещё раз` | повторить, закрыть |
| Данные изменились, объект удалён или ответственный больше не участник | `Кажется, данные устарели` | `Обновитесь до последней версии поездки` | обновить данные |

### Файлы, изображения и импорт

| Сценарий | Заголовок | Подзаголовок | Действия |
| --- | --- | --- | --- |
| Файл не выбран | `Кажется, вы не выбрали файл` | `Нужно выбрать` | закрыть |
| Выбран не рисунок | `Кажется, это не картинка` | `Нужно в формате JPG, PNG или WEBP` | закрыть |
| Фото или аватар больше лимита | `Какой огромный файл` | `Должен быть до 15 МБ` | закрыть |
| Ошибка загрузки аватара на сервер | `Эх, файл не загрузился` | `Попробуйте ещё раз` | повторить, закрыть |
| Файл импорта повреждён | `Кажется, файл повреждён` | `Попробуйте загрузить другой файл` | закрыть |
| Неподходящий формат импорта | `Не тот формат файла` | `Нужен формат .travelspace` | закрыть |
| В архиве некорректные данные | `Эх, поездка не загружается` | `В ней есть некорректные данные` | закрыть |
| Неизвестная ошибка импорта | `Эх, поездка не загружается` | `Попробуйте ещё раз` | повторить, закрыть |
| Архив импорта больше лимита | `Какой огромный файл` | `Должен быть до 200 МБ` | закрыть |
| Не скачался экспорт | `Эх, поездка не скачивается` | `Попробуйте ещё раз` | повторить, закрыть |

### Права, приглашение и общая ошибка

| Сценарий | Заголовок | Подзаголовок |
| --- | --- | --- |
| Пользователь больше не состоит в поездке | `Нет доступа к поездке` | `Обратитесь к её владельцу` |
| Корректное приглашение не удалось принять | `Ох, не присоединяется` | `Попробуйте ещё раз` |
| Неизвестная общая ошибка | `Ох, что-то отвалилось` | `Попробуйте ещё раз` |

Шаблон отсутствия доступа общий для всех операций: бессмысленно перечислять действие,
если причина всегда одна. Попытка участника удалить чужой файл является исключением:
это понятная локальная ошибка строки и показывается у `InfoRow`.

### Успешное сохранение

Успешное системное уведомление:

- заголовок `Всё сохранилось`;
- подзаголовок `Можете закрывать страницу`;
- единственное действие — крестик.

## 5. Системные состояния

Когда не удалось открыть весь экран или раздел, используются тексты:

- `Поездка не найдена`;
- `Не удалось открыть поездку`;
- `Не удалось открыть аккаунт`;
- `Не удалось принять приглашение`;
- `Не удалось загрузить список участников.`

## 6. Сценарии сохранения

### Профиль, поездка, отель и транспорт

После успешного сохранения экран не закрывается. Нижняя кнопка проходит состояния:

1. `Сохранить` или `Сохранить поездку` — есть несохранённые изменения;
2. `Сохраняем…` — запрос выполняется, кнопка неактивна;
3. `Изменения сохранены` — запрос завершён, кнопка неактивна.

После следующего изменения поля кнопка снова становится активной и возвращает обычный
текст. Правило применяется к профилю, поездке, отелю и транспорту, включая билетные
данные формы.

### Город

После сохранения города интерфейс возвращается к настройке поездки и показывает
успешное уведомление. Сохранение города не закрывает всю работу с поездкой.

## 7. Даты и целостность маршрута

- Изменение дат поездки больше не удаляет города автоматически.
- Город вне нового диапазона остаётся в списке, получает ошибку у `InfoRow`, а
  сохранение поездки блокируется до исправления дат.
- Если сервер обнаружил такие города, показывается `Эх, не сохраняется` /
  `Проверьте даты городов`.
- При сужении дат уже существующего города места вне нового диапазона автоматически
  переводятся в `Без даты` на клиенте и сервере.
- Конфликт версии, удалённый объект и ответственный, исключённый из поездки, используют
  общий шаблон устаревших данных с явным обновлением.

## 8. Удаление города

Нажатие корзины запускает подтверждение сразу, а не после нажатия общей кнопки
сохранения.

Если в городе есть места или файлы, пользователь должен ввести точное название:

- заголовок: `Удалить «{Название города}»?`;
- пояснение: `Все локации и файлы из него будут удалены. Для подтверждения введите название города.`;
- основное действие: `Удалить город`;
- при несовпадении: `Такого города не существует`.

Пустой город использует короткое подтверждение. Удаление фиксируется в черновике
настройки поездки и окончательно применяется при сохранении поездки; сервер каскадно
удаляет места, документы и физические файлы.

Попытка удалить уже отсутствующий объект не считается обычной ошибкой удаления:
показывается шаблон `Кажется, данные устарели` с обновлением поездки. Сценарий удаления
владельца поездки в интерфейсе отсутствует.

## 9. Компонентные решения

- `InfoRow` поддерживает error-state наравне с `Input` и `Select`.
- Выбор стиля заголовка доступен только у прозрачной строки без фона. Строки с фоном
  всегда используют стиль `Text`; это закреплено на уровне компонента.
- Правило применяется к городам, участникам, изображениям, документам и строкам
  `Итого по людям`.
- В библиотеку иконок добавлена актуальная SVG-иконка предупреждения.

## 10. Страница «Контент»

Страница обязана демонстрировать все пользовательские тексты из этой спецификации.
Группы ошибок находятся в конце навигации и разделены на:

1. ошибки полей;
2. ошибки `InfoRow`;
3. успешные уведомления;
4. уведомления об ошибках;
5. системные ошибки.

При изменении текста или поведения сначала обновляется продуктовый экран, затем в том
же изменении обновляется соответствующий пример в `ComponentContentPreview`.

## 11. Исключённые и объединённые случаи

- Функциональность задач не входит в текущий продукт и не должна порождать интерфейсные
  ошибки или примеры в «Контенте».
- `Некорректная сумма оплаты` не выделяется в отдельный пользовательский сценарий,
  потому что обычный денежный контрол не позволяет воспроизвести его корректным UI.
- Отдельные тексты `место/файл/поездка/участник не найден` объединены в шаблон
  устаревших данных.
- Ошибки `город не найден` при работе с файлами также сводятся к обновлению данных.
- Изменение фото города и фона недоступно участнику на уровне интерфейса; отдельный
  пример ошибки для этой невозможной операции не нужен.
